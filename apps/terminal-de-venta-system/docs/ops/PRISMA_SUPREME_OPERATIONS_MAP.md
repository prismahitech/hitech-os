# PRISMA Supreme Operations Map

## Plan-Based Client Onboarding / Auto Provisioning

This section is the canonical operations map for one-shot customer onboarding by plan. The operator chooses customer + plan once, and the existing Customer Setup flow creates the license, license assignment, setup bundle, setup code, setup link, setup QR payload, device claim slots, and audit trail.

Canonical implementation:

```text
shared/licensing/customer-setup-contract.ts
infra/cloudflare/licflow3-worker/src/worker.js
infra/cloudflare/licflow3-worker/migrations/0003_plan_based_provisioning.sql
tools/verify-customer-setup-multidevice.mjs
```

Historical migration `0002_customer_setup.sql` remains the base Customer Setup migration. Plan provisioning is additive in `0003_plan_based_provisioning.sql`.

Operator action:

1. Create or select the customer.
2. Choose the plan.
3. Confirm the one-shot onboarding action.
4. Share the generated Setup Link, Setup Code, or Setup QR.

Operator must not manually create one device claim per Tablet, PC, or Mobile device. Tablet, PC, and Mobile claim against the prepared slots generated by the plan.

Participating tables and endpoints:

| type | canonical item |
| --- | --- |
| Admin create endpoint | `POST /api/admin/customer-setups/create` |
| Customer resolve endpoint | `GET /api/customer/setup/:setupCode` |
| Device claim endpoint | `POST /api/customer/devices/claim` |
| Status endpoint | `GET /api/customer/license/status?setupCode=:setupCode&deviceId=:deviceId` |
| Base setup tables | `customer_setups`, `customer_setup_slots`, `customer_device_claims` |
| Plan provisioning tables | `license_plans`, `license_assignments`, `customer_setup_bundles`, `customer_device_claim_slots` |
| Audit events | `customer_setup.create`, `customer_setup.plan_based_provision` |

This is the operational provisioning matrix. It must not be interpreted as the commercial SKU catalog.

Flow notes:

| step | actor | function/route | artifact created | pass/fail rule |
| --- | --- | --- | --- | --- |
| Choose customer and plan | Operator | `POST /api/admin/customer-setups/create` | plan-bound setup request | Must happen once per customer onboarding. |
| Resolve plan | Cloud License Gateway | `resolveCustomerSetupPlan` | `PlanProvisioningDefinition` | Unknown plans fall back to canonical default, not a parallel catalog. |
| Create license assignment | Cloud License Gateway | `upsertLicenseAssignment` | `license_assignments` row | Must link customer, plan, license, and bundle. |
| Create setup bundle | Cloud License Gateway | `upsertSetupBundle` | `customer_setup_bundles` row | Must include setup code, link, QR, expiration, and audit id. |
| Generate prepared slots | Cloud License Gateway | `buildDeviceClaimSlotsForPlan` and `upsertDeviceClaimSlot` | `customer_device_claim_slots` rows | plan -> slots must match per-surface limits. |
| Claim Tablet | Tablet POS | `POST /api/customer/devices/claim` | claimed tablet slot | Tablet consumes a prepared slot. |
| Claim PC | PC/Admin | `POST /api/customer/devices/claim` | claimed pc slot | PC consumes a prepared slot only if the plan allows pc. |
| Claim Mobile | Mobile | `POST /api/customer/devices/claim` | claimed mobile slot | Mobile consumes a prepared slot only if the plan allows mobile. |
| Audit create | Cloud License Gateway | `recordAudit` | `customer_setup.create` | PASS requires sanitized setup creation evidence. |
| Audit provisioning | Cloud License Gateway | `recordAudit` | `customer_setup.plan_based_provision` | PASS requires plan/license/bundle audit evidence. |
