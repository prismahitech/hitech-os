# Canonical Registration Foundation V1

Capability: visual.canonical_promotion_integration_v1

This is the bounded write boundary between promotion resolution and existing visual authorities. It is not GVAE and does not perform browser/runtime mutation.

## Authority boundaries

- Workers remain proposal-only.
- NDC remains the semantic canonical writer for neutral meaning.
- Identity remains visual-meaning, recipe and adapter authority.
- RIFAT remains exact location/layer/projection authority.
- Target Index remains generated by its governed generator; this capability never hand-edits the manifest.
- GVAE remains the exact application/control engine after registration.
- Atlasfin remains reference/evidence only.

## V1 transaction contract

A request must pin an exact target, expected main HEAD, current-truth snapshot, source digest, explicit semantic adjudication, exact binding, application-layer policy and mutation authorization.

Automatic semantic inference and automatic application-source selection are rejected. Existing IDs are immutable. Target and application-layer IDs have no generic allocator and therefore fail closed until their owning authority supplies an explicit authorized ID.

The plan is generated before any write and contains an explicit mutation set restricted to allowlisted canonical Identity registries. The result distinguishes APPLIED from NO_OP_IDEMPOTENT. Receipts preserve request/current-truth/source digests and pre/post authority hashes.

Rollback is transaction-scoped and refuses to overwrite newer work.

## Deliberate boundary

This foundation does not pretend to have an NDC writer, RIFAT writer or Target Index generator of its own. Those existing authorities must be connected through explicit adapters in the next implementation slice. No new semantic registry is introduced.
